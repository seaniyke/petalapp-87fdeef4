- Build outcomes go through `src/lib/build-outcome.ts` `decideBuildOutcome` and refunds through the guarded `refund_build_charge` (refuses ready/stale/same-revision-delivered builds); every variable cost is one append-only `cost_events` row with basis ACTUAL/ESTIMATED/ALLOCATED/UNKNOWN; free credits are build-only via `is_build_credit_reason` inside `spend_credit` — why: stale callbacks must never refund delivered work, and costs/credit purposes need one authority each.
- Failure origin is classified once in `src/lib/failure-classification.ts`; only `code` failures may justify destructive recovery, and AI-backed repairs throw `InfrastructureFailure` on provider errors — why: a provider 502 during repair deleted a valid App.tsx.
- UI "active/complete" derives from `src/lib/turn-execution/activity-state.ts`; a terminal authoritative lifecycle overrides every local flag — why: spinners latched after failed turns.
- Failure cards derive origin/headline/action/preserved from `failure-classification.ts` via `classify()` in `friendly-errors.ts`; components never classify — why: one failure authority for every card.
- `build-phases.ts` is caption-only (labels, icons, elapsed); active/terminal state comes only from `deriveActivityState` — why: phases must never decide lifecycle.
- A non-committed turn's final message comes only from `src/lib/terminal-result.ts` (`buildTerminalResult`/`formatTerminalResult`), replaces the model narration, and is persisted server-side with the assistant reply (Railway builder may insert `messages` pinned to its project) — why: the hospital failure said "everything else landed" and vanished on reload.
- Build billing: one pricer `src/lib/build-pricing.ts` (cost/credit = revenue × (1−margin) from economics_config; min 0.05, round up 0.01); credits reserved before work via `reserve_build_credits` (class p90 or default × headroom), settlement capped at the hold with no customer debt, holds released exactly once by `release_build_reservation`/turn-end trigger — why: charge measured cost, never surprise or double-charge.
- Customer price comes only from the effort curve in `src/lib/effort-pricing.ts` (`effortScore` over productive authored work, scaffold excluded → `creditsForEffort`, floor 0.30, capped by the hold; all weights/curve in `economics_config` `effort_*`); internal cost comes only from the saved per-call records and feeds margin, flags and the spending limit (class cost × headroom), never the price — why: Kimble sells completed work, not tokens, and customers must never pay for Kimble's waste.
- Kimble Cloud charges go only through `src/lib/cloud-pricing.ts` (external price = provider cost ÷ (1 − `cloud_external_margin_pct`); Shared = equivalent dedicated price × (1 − `cloud_shared_discount_pct`); credits = price ÷ `revenue_per_credit_usd`) and `src/server/cloud-metering.server.ts` `chargeCloud` (one `cost_events` row per resource, idempotent per window, then `chargeRuntime` with exact credits); Railway is priced from its `usage` API (ESTIMATED fallback), Supabase from the project's compute add-on rate, Shared from the shared bill allocated by rows (UNKNOWN until entered) — why: flat hourly guesses hid Kimble's real cost and Shared Cloud earned nothing.
