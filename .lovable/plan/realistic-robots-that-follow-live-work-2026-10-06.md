# Realistic robots that follow live work

## What changes
- Replace the small cartoon robot icons with realistic, articulated 3D robots: metallic shells, mechanical joints, illuminated face panels, and believable task-specific movement.
- Show the robot scene inside the chat from the first genuine thinking stage—not only after the build activity panel appears.
- Keep the four roles: Architect, Builder, Inspector, Launcher. Planning examines a work surface, building operates articulated tools, checking scans the work, and launching activates the release station.
- Preserve the smooth iOS chat, compact rectangular controls, and all existing build behavior.

## Real-time behavior
- Real execution updates select the active robot and current action. Existing file names and progress captions remain the evidence of work.
- Motion runs only while that work is active. Stop, failure, completion, and waiting for an answer halt working animations.
- No timed phase cycling, invented percentages, or claims that these figures are additional AI agents. They visualize Kimble's existing execution engine.
- Show one scene at a time, avoiding duplicates when the detailed build panel appears.

## Technical details
- Use a client-loaded Three.js scene with procedural robot geometry and semantic theme tokens; no changes to generation, billing, Cloud, or orchestration.
- Drive activity through the existing authoritative lifecycle helper and phase updates. Mount the scene outside the conditional activity card so initial thinking is covered.
- Use stable scene dimensions, mobile-friendly rendering limits, visibility-based pausing, reduced-motion support, and a static fallback if 3D rendering is unavailable.

## Verification
- Check planning, writing, checking, launching, stopped, failed, and completed states with deterministic UI fixtures.
- Inspect desktop and phone layouts, light/dark appearance, movement, legibility, and absence of overlapping controls.
- Verify the actual active chat integration separately from the fixtures; do not claim live build proof from a demonstration alone.
- Provide a screenshot and short animation of the finished appearance, labeling demonstration footage honestly if a live run is unavailable.
